# REVIEW.md

## Defects Identified and Resolved in the Starter Implementation

| # | Function / Area | Defect | How to Detect | Fix |
|---|---|---|---|---|
| 1 | `health()` | Static 200 response without checking MongoDB connectivity. If the database is down, it still reports ready. | Stop MongoDB or configure an invalid port and call `GET /health`. It returned 200 OK instead of 503. | Added `client.admin.command("ping")` within 5-second timeout; returns HTTP 503 on database failure. |
| 2 | `compute_late_minutes()` | Incorrect grace period boundary and overnight shift calculation. Evaluated `minutes > 10` after integer conversion; replaced date directly with punch_in date for overnight shifts. | For 09:30 shift: `09:40:00` must be 0, `09:40:01` must be 10, `10:15:59` must be 45. For 22:00 shift punching in at `00:15` next day, starter produced negative time and 0 late minutes instead of 135. | Anchored shift start datetime to the IST attendance date; strictly checked `elapsed_seconds > 600` before calculating `int(elapsed_seconds // 60)` from shift start. |
| 3 | `compute_work_hours()` | Python built-in `round()` uses round-to-even (banker's rounding), violating business rule R4. | Test elapsed seconds resulting in `.005` (e.g. 18 seconds = 0.005 hours rounds to 0.00 instead of 0.01). | Used `Decimal` with explicit `ROUND_HALF_UP` quantization to two decimal places. |
| 4 | `compute_overtime()` | Missing 30-minute threshold check and failure to handle overnight shift endings. | Overtime of 15 minutes was reported as 15 instead of 0. Overnight shifts (22:00 to 06:00) did not advance shift_end to the next calendar day. | Advanced shift_end datetime by +1 day when `shift_end <= shift_start`; returned 0 overtime if elapsed time is strictly less than 1800 seconds (30 minutes). |
| 5 | `create_employee()` | Missing duplicate-key error handling on concurrent inserts; missing input format validation; `created_at` stored as naive local time and serialized as string. | Send parallel POST requests with the same `emp_code` (triggered unhandled 500 error). Send `emp_code="invalid"`, `shift_start=="shift_end"`. Inspect `created_at` response type. | Added Pydantic field regexes, validators for `shift_start != shift_end` and `joined_on` date format. Handled `DuplicateKeyError` to return 409. Normalized `created_at` to UTC whole seconds and returned integer epoch milliseconds. |
| 6 | `list_employees()` | Page 1 skipped due to `skip = page * page_size`; `total` was calculated over entire collection rather than matching filter query; `created_at` not formatted as epoch milliseconds. | Request `/employees?page=1&department=Engineering`. Page 1 returned the second page of records; `total` showed total company count instead of department count. | Corrected skip calculation to `(page - 1) * page_size`, filtered count query with `q`, and converted `created_at` to integer epoch milliseconds. |
| 7 | `punch_in()` | No employee existence validation; unhandled race condition on concurrent duplicate punch-ins; overnight shifts assigned to wrong calendar date; exposed internal `id` / `_id`. | Punch in with non-existent `emp_code` (succeeded or corrupted logs). Send parallel punch-ins (threw 500). Punch in at 05:45 IST on overnight shift 22:00-06:00 (assigned to today rather than yesterday's shift). Inspected response body. | Added 404 employee check. Used unique compound index `uq_attendance_emp_code_date` and handled `DuplicateKeyError` returning 409. Applied R1 overnight shift rule. Stripped `_id` and `id`, returning schema-compliant `AttendanceRecord`. |
| 8 | `list_attendance()` | In-memory sorting and pagination using `list(db.attendance_logs.find(q))`; no validation for `date_from > date_to`; missing legacy fields defaults (`history`, `half_day`). | Call `/attendance` on a collection with 100k documents (high memory usage and latency). Call `/attendance?date_from=2026-07-10&date_to=2026-07-01` (returned 200 instead of 422). | Implemented database-level sorting, skip, and limit backed by index `idx_attendance_date_emp_code`. Validated date bounds with 422 error. Defaulted missing legacy fields according to specification. |
| 9 | `punch_out()` | Missing from starter. | Call `POST /attendance/punch-out` (404 route not found in starter). | Implemented endpoint finding most recent punch-in record; verified `punched_at > punch_in` and `<= 24h` (422); atomically updated with `punch_out: None` condition returning 409 on race conditions; computed derived fields (R3, R4, R5). |
| 10 | `regularize_attendance()` | Missing from starter. | Call `PATCH /attendance/{emp_code}/{date}` (404 route not found in starter). | Implemented regularization endpoint with validation: cleared punches on `ABSENT`/`LEAVE`, verified presence status punch-in, enforced date consistency, rejected no-op requests (422), and atomically appended immutable history entry with optimistic locking to prevent race conflicts. |
| 11 | Analytics endpoints | Missing from starter: `employee_monthly`, `department_summary`, `late_leaderboard`, `department_trend`. | Call any `/analytics/*` route (404 route not found in starter). | Implemented all 4 analytics endpoints using MongoDB aggregation pipelines: correct Mon-Fri working days and half-day present days; cross-collection department headcount including zero-log employees; standard competition ranking (1, 2, 2, 4) with ties at cutoff; daily trend gap-filling with `$densify` and 7-day moving average. |
| 12 | `admin_explain()` | Missing from starter. | Call `GET /admin/explain/{endpoint}` (404 route not found in starter). | Implemented explain endpoint running `db.command("explain", ...)` with `executionStats` for all five operations. Backed all queries with indexes, ensuring `IXSCAN` and zero `COLLSCAN`. |

## Architectural Decisions Examined & Retained

- **Natural Key Addressing**: Maintained `(emp_code, date)` as the natural unique key for attendance records and `emp_code` for employees, keeping internal `_id` completely encapsulated.
- **Authoritative Stored Derived Fields**: Kept derived fields (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`) stored directly in documents and read by analytics aggregations without dynamic recomputation.
- **FastAPI + PyMongo Stack**: Utilized synchronous PyMongo with connection pooling and server selection timeouts to provide deterministic latency and full aggregation support.
